# PangeaVPN iOS

SwiftUI app plus a Packet Tunnel network extension. The tunnel and hub control
plane come from the same Go core as Android, built into a static
`Pangeacore.xcframework` with `gomobile` and linked into both targets.

## Targets

| Target | What it is |
|---|---|
| `daemon/mobile` (Go) | gomobile source, shared with Android. Builds to `Frameworks/Pangeacore.xcframework` (gitignored). |
| `PangeaVPN` | The app (`org.pangeavpn.app`): control plane, screens, settings. |
| `PacketTunnel` | The `NEPacketTunnelProvider` extension (`org.pangeavpn.app.tunnel`): runs the tunnel on the utun fd. |
| `PangeaVPNTests` | Unit tests, hosted by `PangeaVPN`. |
| `Shared/` | Sources compiled into both the app and the extension. |

The project is generated by XcodeGen from `project.yml`. `PangeaVPN.xcodeproj`
and `Generated/` (Info.plists and entitlements) are gitignored outputs; edit
`project.yml`, never the generated files. New `.swift` files dropped into a
target's folder are picked up on the next `xcodegen generate`.

Both targets carry the `packet-tunnel-provider` Network Extension entitlement
and the App Group `group.org.pangeavpn.app`, which also serves as the Keychain
access group.

## Prerequisites

- macOS with Xcode 16+ (iOS 17.0 deployment target, Swift 5 language mode)
- Go 1.26+ and `gomobile`, installed from `daemon/` so the CLI matches the
  `golang.org/x/mobile` version pinned in `daemon/go.mod`:
  ```bash
  cd daemon
  go install golang.org/x/mobile/cmd/gomobile golang.org/x/mobile/cmd/gobind
  ```
- XcodeGen 2.44.1 (the version CI pins): `brew install xcodegen`, or the
  release zip from the XcodeGen GitHub releases page.

## Build

### 1. Build the Go core xcframework

From `daemon/`, the Go module root:

```bash
gomobile bind -target=ios,iossimulator -iosversion=17.0 \
  -tags=with_utls -ldflags=-checklinkname=0 \
  -o ../apps/ios/Frameworks/Pangeacore.xcframework \
  ./mobile
```

The tags and ldflags are the Android AAR's; `apps/android/README.md` explains
both. The module is named after the output file, so Swift does
`import Pangeacore`, and Go functions appear as `Mobile*` C functions.
The framework is static: it is linked, never embedded. Re-run whenever
`daemon/mobile` changes.

### 2. Generate the project

```bash
cd apps/ios
xcodegen generate
```

### 3. Build and test

```bash
xcodebuild test -scheme PangeaVPN -destination 'platform=iOS Simulator,name=iPhone 16'
xcodebuild build -scheme PangeaVPN -configuration Release -destination generic/platform=iOS CODE_SIGNING_ALLOWED=NO
```

Pick any installed iPhone simulator for the test destination. CI
(`.github/workflows/build-ios.yml`) runs the same steps on `macos-15`: the core
job builds the xcframework (cached on the Go sources, Go, gomobile and Xcode
versions; arm64 slices only), then the test and device jobs run in parallel.

## Versioning

`project.yml` holds placeholder versions for local builds. CI reads the root
`package.json`: `MARKETING_VERSION` is its version without any prerelease
suffix (App Store versions are numeric only), and `CURRENT_PROJECT_VERSION`
follows Android's `versionCode` rule (`0.8.1` → `801`).

## Signing

Not set up yet. `project.yml` names no team: simulator builds need none, and
CI's device build runs with `CODE_SIGNING_ALLOWED=NO`.

## Privacy manifests

Both targets ship a `PrivacyInfo.xcprivacy`: UserDefaults (`1C8F.1`, app-group
suite), file timestamps (`C617.1`, Go core inside the container), no tracking,
and the account identifier as collected data. Re-check against Xcode's privacy
report on the first archive.
